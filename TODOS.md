# TODOS

## How to work this list

- **Confirm with the user before implementing a TODO.** No step may be started without the user's explicit go-ahead.
- **Explain before implementing** — before starting a step, explain the problem it addresses and the steps to perform; the user may add refinements, and the step starts only once reconfirmed.
- **Steps are ordered** — do one step at a time; each step is one change set and one commit (commit messages are the change record, per `AGENTS.md`).
- **No bundling** — do not bundle several steps into one change set; if a step turns out bigger than expected, split it further.
- **Steps carry checkboxes** — when a step is done, check it off (`[x]`) and commit it in the changeset.
- **Completed topics are deleted** — a whole topic (heading + its steps) should be deleted when _all_ of its steps are checked.
- **New TODOs** — after defining TODOs with the user, the new TODOs may be committed.
- **User edits** — the user might edit this file himself; commit uncommitted changes with appropriate commit messages.
